# Collector Recommendations by Product and Platform

Last reviewed: **8 October 2026**.

Use this list to choose the first collector to evaluate for a target product. These are engineering recommendations inferred from the documented execution environments and our collector requirements. Manufacturer documentation establishes the platform capabilities; it does not certify Thunderstorm Collector compatibility or authorize its execution.

Unless specific evidence is linked, the product/collector combination is **not yet product-tested**. An alternative has its own prerequisites and is not automatically interchangeable with the preferred collector. Match the actual OS, CPU architecture, firmware, available runtime and permitted access before selecting a file.

### Nutanix execution restrictions

An existing Linux shell does not establish permission to run a collector on AHV or a CVM. A [2020 Nutanix employee advisory](https://next.nutanix.com/installation-configuration-23/antivirus-on-nutanix-ahv-hosts-and-on-cvms-37041) specifically discourages third-party software execution on both. The [current third-party support policy](https://www.nutanix.com/en_gb/support-services/support-policies-and-faqs?show=accordion-0) also describes possible support limitations. Confirm the permitted collection procedure with Nutanix; without that confirmation, prefer approved exports and upload from a separate system. A standalone binary requiring no package installation does not by itself remove this restriction.

## Collector Files and Runtime Requirements

The paths below describe the reorganized source tree. Published releases contain their tagged versions, so consult the matching release instructions and asset list. **As of 8 October 2026, v1.0.1 is the latest published release; v1.0.2 has not been published.** v1.0.1 does not include the revised scripts, the new legacy script variants or the dedicated FreeBSD 8.4 NetScaler package.

- **Go:** select the OS/architecture package from [Releases](https://github.com/NextronSystems/thunderstorm-collector/releases), following the [Go guide](../go/README.md). A static binary still requires a compatible OS/kernel and CPU. The compiler used can differ between targets; do not assume every build uses Go 1.9.7.
- **Python:** [Python 3 collector](../scripts/python/thunderstorm-collector.py), requiring Python 3.4+ and the standard library; [Python 2 collector](../scripts/python/thunderstorm-collector-py2.py), requiring Python 2.7. Verified HTTPS on Python 2 requires 2.7.9+ and a compatible SSL library. See the [Python guide](../scripts/python/README.md). The older v1.0.1 Python script requires Python 3.6+ and has a different interface.
- **Bash:** [Bash collector](../scripts/bash/thunderstorm-collector.sh), requiring Bash 3.2+, curl or GNU wget with `--no-config`, and the utilities in its [guide](../scripts/bash/README.md). It does not require Python or jq.
- **Other execution environments:** use the [script selection guide](../scripts/README.md#choosing-a-collector) for POSIX sh/ash, Perl, PowerShell and Batch. Their capabilities and dependencies differ; for example, the Bash file is not a BusyBox ash script.

## External Collection and File Visibility

External collection means exporting or copying approved files using the product's documented mechanisms, then running a collector on the receiving system with an explicit input directory. It is a workflow, not a built-in SSH/API acquisition mode. Preserve the original files and source identity separately and verify how the backend represents exported filenames and source identifiers.

The collector can upload only files visible and readable in its execution environment and admitted by its filters. An AHV host is not its CVM or its guest VMs; an ESXi host is not vCenter; a container's filesystem is not automatically its node's filesystem. Review size, age, extension and filesystem exclusions for the intended inputs, especially large exports or core files. These recommendations do not establish that Thunderstorm analyzes every possible export format.

## Test Evidence and Future Updates

The [script acceptance report in PR #52](https://github.com/NextronSystems/thunderstorm-collector/pull/52) records exact revisions, runtime versions, hashes and outstanding checks. Its successful real-THOR runs do not certify all products listed above. The [NetScaler/FreeBSD record](../go/README.md#compatibility-evidence-as-of-2026-10-08) separately identifies the tested legacy artifact and VM environments.

For a new product test, record product/firmware, OS and architecture, collector revision or asset hash, runtime, execution context and visible paths, HTTP/HTTPS mode, dry-run outcome and server-side receipt/results. Link that record here before changing a recommendation from an untested candidate to a product-tested combination. Runtime availability, successful startup and successful end-to-end collection are different evidence levels.
